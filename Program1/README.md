# Program 1 – Project plan, product backlog and user stories

## Aim
Prepare a project plan, product backlog and user stories for a sample hall-booking application.

## Project plan
1. Define scope, purpose, objectives and business justification.
2. Break deliverables into a work breakdown structure (WBS).
3. Identify task dependencies.
4. Create a timeline and milestones (a Gantt chart can be used).
5. Estimate the budget, including low- and high-cost options.

## Product backlog
The manual describes the backlog as an ordered list of known product work. Gather ideas from the development team, customers and stakeholders; clarify each item's reason, value and specifications; prioritize high-value work; and refine the backlog regularly.

## Sample user stories
- As a customer, I want to register so that I can use the booking service.
- As a customer, I want to check hall availability by location and date so that I can find a suitable hall.
- As a customer, I want to book an available hall so that I can reserve it.
- As a customer, I want to view and update booking details so that my reservation information stays correct.

## Acceptance criteria
For registration, valid name and phone details should register successfully; invalid details should show an error. For availability, a valid Karnataka location and date should return matching halls; an invalid location should show an error. A booking succeeds only when the selected hall/date is available. Booking details are available only after a booking is made.

Save the scope, WBS, dependency list, timeline, budget estimate, backlog and acceptance criteria in your project record.
